# ADR 0002: Zero-dependency library script

## Summary
Everything mechanical in Ang is done by `ang-context-manager.mjs`: indexes, state, tags, triggers, validation, the session banner, and the core `settings`, `version` and `upgrade` commands. It is plain Node ESM (ECMAScript modules) that imports only Node built-ins: `node:fs`, `node:path`, `node:os` (temp trees in the upgrade), `node:child_process` (`git check-ignore`, `git merge-file`, giget) and `node:crypto` (stream IDs), plus the global `fetch` for release lookups and upgrade guides. Tests add `node:test` and its companions. Ang ships no `package.json`. Installing it needs Node 26+, npx and git ([ADR 0005](/project-context/10k/technical/adrs/0005-install-by-copy-in-from-releases.md)), but nothing is installed for the script itself. Drawn from `src/.claude/scripts/` and `src/.claude/ang/features/` as of 2026-11-23.

## Context
Ang is copied into a repo, often a client's, beside whatever stack that repo already has. A dependency tree would mean a package install in the user's repo and possible clashes, and it would keep needing upkeep.

## Decision
- One CLI entry point is wired into hooks and permissions. Its modules are split by concern under `scripts/ang/`.
- Node built-ins only, with no third-party packages. Tools the install and upgrade need (giget) run through `npx` at a pinned version, never as a dependency of the script.
- The agent-facing files (index, state, triggers) are generated by this script and are never edited by hand.
- `settings`, `version` and `upgrade` are core commands, not feature-gated, because a fresh install has no `ang.json` yet.

## Consequences
- Running Ang needs Node 26+ on the PATH; installing and upgrading also need npx, git and network access to GitHub.
- Any new script capability must be written by hand against the built-ins, or justify adding the first dependency.

## Standing
2026-11-23. Built: the shipped modules import only `node:fs`, `node:path`, `node:os`, `node:child_process` and `node:crypto`, plus global `fetch`; tests add `node:test`, `node:assert/strict` and `node:http`. The repo has no `package.json`.
