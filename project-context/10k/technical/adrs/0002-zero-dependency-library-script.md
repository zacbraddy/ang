# ADR 0002: Zero-dependency library script

## Summary
Everything mechanical about the context library is done by `ang-context-manager.mjs`: indexes, state, tags, triggers, validation and the session banner. It is plain Node ESM (ECMAScript modules) that imports only Node built-ins: `node:fs`, `node:path`, `node:child_process` (for `git check-ignore` in `validate`) and `node:crypto` (stream IDs), plus `node:test` and its companions in tests. Ang has no `package.json` and no install step. This is drawn from the code in `src/.claude/scripts/` and `src/.claude/ang/features/` as of 2026-11-16.

## Context
Ang is copied into a repo, often a client's, beside whatever stack that repo already has. A dependency tree would mean an install step and possible clashes, and it would keep needing upkeep.

## Decision
- One CLI entry point is wired into hooks and permissions. Its modules are split by concern under `scripts/ang/`.
- Node built-ins only, with no third-party packages.
- The agent-facing files (index, state, triggers) are generated by this script and are never edited by hand.

## Consequences
- Running Ang needs only Node on the PATH.
- Any new script capability must be written by hand against the built-ins, or justify adding the first dependency.

## Standing
2026-11-16. Built: the script and feature modules import only `node:fs`, `node:path`, `node:child_process` and `node:crypto`; its tests add `node:test`, `node:assert/strict` and `node:os`. The repo has no `package.json`.
