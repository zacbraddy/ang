# ADR 0002: Zero-dependency library script

## Summary
Everything that ships under `src/` imports only Node built-ins. The main case is `ang-context-manager.mjs`, which does everything mechanical in Ang: indexes, state, tags, triggers, validation, the session banner, and the core `settings`, `version` and `upgrade` commands. It is plain Node ESM (ECMAScript modules) that imports only `node:fs`, `node:path`, `node:os` (temp trees in the upgrade), `node:child_process` (`git check-ignore`, `git merge-file`, giget) and `node:crypto` (stream IDs), plus the global `fetch` for release lookups and upgrade guides. Tests add `node:test` and its companions. Ang ships no `package.json`. Installing it needs Node 26+, npx and git ([ADR 0005](/project-context/10k/technical/adrs/0005-install-by-copy-in-from-releases.md)), but nothing is installed for the script itself. Tooling that only develops this repo lives outside `src/` and may have its own private `package.json` and lockfile; the docs site in `docs/` is the first. Drawn from `src/.claude/scripts/`, `src/.claude/ang/features/` and `docs/package.json` as of 2026-11-23.

## Context
Ang is copied into a repo, often a client's, beside whatever stack that repo already has. A dependency tree would mean a package install in the user's repo and possible clashes, and it would keep needing upkeep. Developing Ang itself is different: a docs site, linting or formatting need packages, and none of that reaches an install.

## Decision
- One CLI entry point is wired into hooks and permissions. Its modules are split by concern under `scripts/ang/`.
- Nothing under `src/` imports a third-party package. Node built-ins only. Tools the install and upgrade need (giget) run through `npx` at a pinned version, never as a dependency of the script.
- Dev-only tooling sits outside `src/`, in a private `package.json` with its own lockfile. It is never installed into a user's repo, and nothing under `src/` imports it. `docs/` (the Starlight site) is one such package; a dev-only root `package.json` for linting and tests fits the same rule.
- The agent-facing files (index, state, triggers) are generated by this script and are never edited by hand.
- `settings`, `version` and `upgrade` are core commands, not feature-gated, because a fresh install has no `ang.json` yet.

## Consequences
- Running Ang needs Node 26+ on the PATH; installing and upgrading also need npx, git and network access to GitHub.
- Any new shipped script capability must be written by hand against the built-ins, or justify adding the first shipped dependency.
- Dev-only packages bring their own upkeep (version bumps, lockfiles). That cost lands on the Ang repo, never on users.

## Standing
2026-11-23. Built: the shipped modules import only `node:fs`, `node:path`, `node:os`, `node:child_process` and `node:crypto`, plus global `fetch`; tests add `node:test`, `node:assert/strict` and `node:http`. `docs/` has its own private `package.json` and lockfile with exact pins. The repo root has no `package.json`.
