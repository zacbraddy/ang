# ADR 0002: Zero-dependency library script

## Summary
Everything that ships under `src/` imports only Node built-ins. The main case is `ang-context-manager.mjs`, which does everything mechanical about the context library: indexes, state, tags, triggers, validation and the session banner. It is plain Node ESM (ECMAScript modules) using `node:fs`, `node:path`, `node:child_process` (for `git check-ignore` in `validate`) and `node:crypto` (stream IDs), plus `node:test` and its companions in tests. So an install of Ang has no `package.json` and no install step. Tooling that only develops this repo lives outside `src/` and may have its own private `package.json` and lockfile; the docs site in `docs/` is the first. Drawn from `src/.claude/scripts/`, `src/.claude/ang/features/` and `docs/package.json` as of 2026-11-18.

## Context
Ang is copied into a repo, often a client's, beside whatever stack that repo already has. A dependency tree would mean an install step and possible clashes, and it would keep needing upkeep. Developing Ang itself is different: a docs site, linting or formatting need packages, and none of that reaches an install.

## Decision
- One CLI entry point is wired into hooks and permissions. Its modules are split by concern under `scripts/ang/`.
- Nothing under `src/` imports a third-party package. Node built-ins only.
- Dev-only tooling sits outside `src/`, in a private `package.json` with its own lockfile. It is never installed into a user's repo, and nothing under `src/` imports it. `docs/` (the Starlight site) is one such package; a dev-only root `package.json` for linting and tests fits the same rule.
- The agent-facing files (index, state, triggers) are generated by this script and are never edited by hand.

## Consequences
- Running Ang needs only Node on the PATH.
- Any new shipped script capability must be written by hand against the built-ins, or justify adding the first shipped dependency.
- Dev-only packages bring their own upkeep (version bumps, lockfiles). That cost lands on the Ang repo, never on users.

## Standing
2026-11-18. Built: the script and feature modules import only `node:fs`, `node:path`, `node:child_process` and `node:crypto`; its tests add `node:test`, `node:assert/strict` and `node:os`. `docs/` has its own private `package.json` and lockfile with exact pins. The repo root has no `package.json`.
