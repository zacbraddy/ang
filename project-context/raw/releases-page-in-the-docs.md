A thought I had while implementing the docs website which I didn't really want to derail the build for because I think there are a few unknowns to work through on it and it's kind of a "nice to have" feature rather than a required one: A lot of OSS repos have a release page in their docs as well the one that is built into the github functionality. I think that would be a nice cherry on top feature for the docs but I think we need to work out how we'd wire it up and that was more work than I think was worth investing mid implementation when we were building the documentation website and threatened to derail it a bit.

I think we need to look around and see if we can work out how other repos are doing it, I'd be shocked if we couldn't hook a way to automate the generation of the page for it. 

I just started to have a thought that we should probably try to work out how to bring in pagination so that the page doesn't grow to large over time and then slapped my self because I spend so much time reminding agents that we aren't expecting too many releases on Ang and here I am building fucking pagination! So not, we don't need pagination let's just let the page grow and show all the releases in chronological order so the latest version shows at the top and the historical versions list below them. Let's make the page layout look nice but I think ultimately the context should pretty much just be driven by the github releases information, at most maybe we could add a bit of static prose to the top of the page if we thought it added value but I doubt anything other than a header really is going to add value but happy to be talked around, maybe the research into how other repos do this can determine what the done thing here is.

So yeah, I think this problem doesn't have so many technical unknowns that would be difficult solving and I doubt there's really any unknown unknowns at all, this all feels extremely doable and not difficult at all. The complication really comes down making a choice between that large number of ways that **we could** achieve this and deciding which path is the right one for me and my comfort levels.
