# Streams conventions

A **stream** is a workspace the user cordons off to work independently on something: one branch in one worktree. What they do in it is their call (any stage, any item, one raw → retro run, or just raising workflow improvements), and Ang runs as usual inside it. Ang does not stop two streams touching the same item; as with two branches editing one file, the merge is the user's. It is opt-in through `streams` in `.claude/ang.json`.

- **Where it lives.** `streams.json` (the registry) and `mail.json` sit on the `ang/streams` branch, which shares no history with main. `ang-context-manager.mjs` reads it with `git show` and writes it with git plumbing, so no worktree checks it out, and each write is pushed to origin as a best effort. Its commits are the one exception to "workflow commands leave changes unstaged": it is infrastructure, not project content.
- **Registry entry:** slug, branch (`stream/<slug>` by default), worktree path, optional one-line focus. There is no item ownership or status: a stream nobody is working in just waits. A checkout's stream is the entry whose branch is its `HEAD`; main is not a stream.
- **Lifecycle** is user-invoked only: `/start-stream <slug> ["focus"]` and `/end-stream <slug>`. `stream set <slug> --focus <text>` rewords the focus line.
- **Mail** is user-approved in both directions, and no mail is the normal outcome. Agents suggest a note only at a skill's mail checkpoint, when news would change what another stream does or decides, and send it only on their yes (main can send, as `main`; nothing is addressed to main and there is no broadcast). Receiving is `read-mail.md`: the agent proposes a disposition per note, the user approves, and handling deletes the note. A note belongs to its recipient: when a stream ends, the notes it *sent* stay in their recipients' inboxes, and only notes *addressed to* it must be forwarded, recorded or dropped.
- **Peeking** is read-only. Worktrees share one object store, so `git show <branch>:<path>` and `git grep <term> <branch> -- project-context` read another stream without checking it out. `context-scout` checks the registry's focus lines first and peeks only when a question plausibly touches another stream.
- **Cross-stream triggers.** A `stream:<stream>:<story:|stage:|file: condition>` trigger condition is judged on that stream's branch through git, so only committed work counts. An unregistered stream, a deleted branch or an item missing from that branch makes the condition gone. Re-point or remove such triggers when a stream ends.
- **Merging between streams.** Regenerate `index.json` after a merge (`ang-context-manager.mjs library index`) rather than merging it by hand. Merge `tags.json` as a union of both sides' tags. `10k/` changes only on main through `/retro`, so streams merge main to pick it up.
- **Validate** (streams on) warns when a registered stream's branch or worktree is gone, or when mail is addressed to an unregistered stream.
