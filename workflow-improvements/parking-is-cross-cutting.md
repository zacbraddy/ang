# Make parking cut scope a cross-cutting convention

**Problem:** Only `/ideate` is told to write to `ideas/parked.md`. Any other step that cuts doable-but-not-yet-valuable work records it only in that item's own docs, so `/refine-ideas` and `/retro` (the steps that check wake conditions) never surface it again.
**Example:** In `/shape-ideas` on generic-personal-defaults (2026-11-16) the per-user intent garnish was cut on YAGNI (you aren't gonna need it) grounds. It was recorded only in `shaping/generic-personal-defaults/shaping-content/tailoring.md` and would have been lost if Zac hadn't asked about it.
**Proposed change:** Add one shared line saying that any workflow step that cuts or defers doable-but-not-yet-valuable work adds an `ideas/parked.md` entry with a wake condition. Put it in `src/.claude/rules/context-library.md` (Writing) or in the README "Moonshots & parked work" section, not in every skill, in line with Ang's lean principle. Update that README section too: it currently describes the lists as "for threads `/ideate` keeps", and the entry source as "raw filename plus commit hash". Widen the source to "raw filename plus commit hash, or the item doc/session that cut it". Keep `/ideate`'s raw-specific instruction as it is. Check whether `/shape-ideas` or `/plan-epic` need a one-word pointer to the convention, and add one only if the shared line alone doesn't get picked up.
**Files:** `src/.claude/rules/context-library.md`, `project-context/README.md` (Moonshots & parked work), possibly `src/.claude/skills/ideate/SKILL.md` line 39 (wording only), and maybe `src/.claude/skills/shape-ideas/SKILL.md`, `refine-ideas`, `plan-epic`, `implement-story`, `review-story` and `retro` if a pointer turns out to be needed
